# QuickEx Contract Entrypoint Reference

This document is the current reference for the public interface exposed by the QuickEx Soroban contract in `src/lib.rs`. It is intended to replace the need to read raw Rust source to answer four questions:

- What does this entrypoint do?
- Which caller is allowed to invoke it?
- What does it return?
- Which `QuickexError` variants can it raise?

> Important: the current contract does not expose a live `create_escrow` entrypoint. Any references to a legacy `create_escrow` stub are stale and should be treated as historical notes only. The supported API is the set documented here.

## Pause and emergency behavior

The contract uses a layered safety model:

- Global pause: admin-controlled pause/unpause state.
- Feature pause flags: narrower operational pauses for deposit/withdrawal/privacy flows.
- Emergency mode: an irreversible, contract-wide safety state. In emergency mode, only a restricted allowlist of entrypoints can run (`withdraw`, `refund`, `stealth_withdraw`, `cleanup_escrow`, `extend_escrow_ttl`).

The allowlist is defined by `pause_policy::EntryPoint::is_emergency_safe()` and enforced by `pause_policy::require_entry_allowed()`.

## Authorization legend

- None: no authentication required.
- Caller must authorize: the function requires the relevant address to sign the call.
- Admin: callable only by the current admin address.
- Admin or Operator: allowed for admin or operator role holders.
- Any caller: anyone may invoke it if state is valid.
- Owner / original depositor: the escrow owner or original depositor is checked.
- Arbiter: the escrow's assigned arbiter is checked.

## Error legend

`QuickexError` is the canonical return type for state-changing entrypoints. The most relevant variants are listed below; not every function returns every variant.

- Validation: `InvalidAmount`, `InvalidSalt`, `InvalidPrivacyLevel`, `BatchSizeExceeded`
- Authorization / admin: `Unauthorized`, `AlreadyInitialized`, `InsufficientRole`, `NoPendingAdminProposal`, `AdminTimelockNotElapsed`, `InvalidAcceptor`
- Escrow / state: `ContractPaused`, `PrivacyAlreadySet`, `CommitmentNotFound`, `CommitmentAlreadyExists`, `AlreadySpent`, `InvalidCommitment`, `CommitmentMismatch`, `EscrowExpired`, `EscrowNotExpired`, `InvalidOwner`, `NoArbiter`, `InvalidDisputeState`, `NotArbiter`, `OperationPaused`, `InvalidContractVersion`, `Overpayment`, `ReentrancyDetected`, `HookAlreadyRegistered`, `HookNotRegistered`, `NotAnArbiter`, `ArbiterAlreadyVoted`, `InsufficientVotes`, `HookNotAllowed`, `EscrowArchived`, `TtlOutOfBounds`
- Stealth / oracle: `StealthAddressMismatch`, `StealthAddressAlreadyUsed`, `StealthEscrowNotFound`, `OracleStalePrice`, `OraclePriceUnavailable`, `OraclePriceInvalid`, `OracleInsufficientSources`, `OracleSourceAlreadyRegistered`, `OracleSourceNotRegistered`
- Replay / signature: `NonceAlreadyUsed`, `SignatureExpired`
- Internal / safety: `InternalError`, `InvalidTimeout`

## Deprecated or legacy entrypoints

The following endpoints exist to preserve compatibility with older deployments and should be treated as legacy surfaces:

- `enable_privacy`, `privacy_status`, and `privacy_history` are the legacy numeric privacy API (Issue #862 / SC-W8-01: now thin shims over the canonical boolean state in `crate::privacy`, so they cannot disagree with `set_privacy`/`get_privacy`). Prefer `set_privacy` and `get_privacy` for new clients.
- `create_escrow` is not a current public entrypoint in this contract. Any mention of it in older docs or commentary should be treated as a stale stub, not an active API contract.
- The contract also still accepts legacy SHA256-based amount commitments during verification in `commitment::verify_amount_commitment`; this is compatibility behavior, not a new primary commitment format.

## Contract-specific notes for contributors

- The public interface is intentionally large and spans escrow lifecycle, privacy toggles, admin operations, fee routing, oracle state, and upgrades.
- The pause affordances are centralized in `pause_policy.rs` and should be checked before adding any new state-changing entrypoint.
- Emergency mode is intentionally restrictive: safety first, while allowing only recovery and maintenance paths.
- When updating this API, use the same pattern as the existing functions: document purpose, auth, return type, and allowed error variants in the rustdoc block above the entrypoint itself, and then mirror the key details here.
